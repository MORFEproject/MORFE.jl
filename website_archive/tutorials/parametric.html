Geometry as a coordinate

Literate script — standardized walkthrough ↗

Carry a shape parameter inside the reduced-order model: one solve describes a whole family of geometries, and the frequency sensitivities fall out of the reduced dynamics.

Runs today — current code

The code below is examples/07_parametric_arch and examples/04_parametric_clamped_beam. Their main.jl files are textually identical — the physics lives in config.jl.

What this tutorial demonstrates

  • Treating a shape parameter as a ROM coordinate: one solve covers a family of geometries.
  • The general additive formulation — any number of independent shape fields.
  • Per-parameter (box) truncation of the θ-series, and why it matters.
  • Reading parametric sensitivities straight off the reduced dynamics, and checking them against FEM identities.

Geometry as a coordinate

Instead of re-meshing and re-reducing for every geometry, let the reference configuration depend on parameters $\boldsymbol\theta = (\theta_1,\dots,\theta_{N_\theta})$, each scaling an independent shape field $\psi_i$:

$$\mathbf x(\boldsymbol\theta, \mathbf x_0) = \mathbf x_0 + \sum_i \theta_i\,\psi_i(\mathbf x_0), \qquad \mathbf J(\boldsymbol\theta, \mathbf x_0) = \mathbf J_0(\mathbf x_0) + \sum_i \theta_i\,\nabla\psi_i(\mathbf x_0).$$

Pulling the weak form back to the reference mesh makes every operator a polynomial in $\boldsymbol\theta$. Using the cofactor identity $\mathbf J^{-1} = \operatorname{adj}\mathbf J/\det\mathbf J$, one factor of $1/\det\mathbf J$ cancels the volume element, leaving

$$\mathbf K(\boldsymbol\theta) \sim \varepsilon_{\rm adj}(\mathbf v)\!:\!\sigma(\varepsilon_{\rm adj}(\mathbf u))\,(1/\det \mathbf J)^1, \qquad \mathbf g \sim (1/\det \mathbf J)^2, \qquad \mathbf h \sim (1/\det \mathbf J)^3.$$

The parameters then enter the DPIM as frozen external states ($\dot\theta_i = 0$), so the reduced dynamics $\dot{\mathbf z} = \mathbf R(\mathbf z, \boldsymbol\theta)$ is a polynomial in the modal and geometric coordinates at once.

Truncation: per parameter, not total degree

The θ-series is truncated on a multiindex box ($k_1 \le N$ and $k_2 \le N$), not by total degree ($k_1 + k_2 \le N$). An earlier two-parameter implementation used total-degree truncation and is superseded; references produced with it are not comparable.

01

Declare the shape fields

A geometry provider returns $(\mathbf J_0, \nabla\psi_1, \dots)$ at a quadrature point. Analytic fields need only the coordinate; fields that are themselves FE solutions get the element and quadrature context. 

# 07 — analytic sinusoidal arch: x(θ,x₀) = x₀ + (1+θ)·w(x₀)
GEOM(x₀) = arch_jacobian_pair(x₀, H0, L_SPAN)

# 04 — ψ₁ uniform axial stretch (constant), ψ₂ = first bending eigenmode (FE field)
function (g::BeamParametricGeom)(x₀, cell, cv, q)
    J₂ = Tens3(function_gradient(cv, q, g.φe))
    return (one(Tens3), g.J₁, J₂)
end
02

Choose the θ-box and assemble

GeometryParameterBasis is the per-parameter box. Separate bases retain exactly the degree required by each structural form. 

BASIS_K = PG.GeometryParameterBasis([GEOM_T1, 2])
BASIS_QUAD = PG.GeometryParameterBasis([GEOM_T1, 3])
BASIS_CUBIC = PG.GeometryParameterBasis([GEOM_T1, 4])
GEOMETRY_PARAMETER_BASES = (; linear = BASIS_K,
    quadratic = BASIS_QUAD, cubic = BASIS_CUBIC)
Exact degrees are known

For a degree-1 Jacobian series, $\det\mathbf J$ is exactly cubic and $\operatorname{adj}\mathbf J$ exactly quadratic, so the elastic forms have known finite θ-degrees (for the arch: 2 for $\mathbf K$, 3 for $\mathbf g$, 4 for $\mathbf h$) — the example sets one basis per form rather than over-truncating.

03

Nonlinear maps and linear corrections

parametric_model pulls the structural forms back through the geometry and returns the assembled parametric case consumed by the common API. 

pcase = SVK.parametric_model(dh, cv, GEOM;
    geometry_parameter_basis = GEOMETRY_PARAMETER_BASES,
    material = MATERIAL, damping = DAMPING, free = free)
K0, M0 = SVK.base_operators(pcase)
04

Solve on an anisotropic multiindex set

Modal and geometric coordinates deserve different orders: high in $(z_1,z_2)$, low in $\boldsymbol\theta$. The set is passed straight to the same parametrise front door the basic examples use. 

mset = MultiindexSet([SVector{NVAR, Int}(a, b, c, d)
    for a in 0:MAXZ for b in 0:MAXZ
    for c in 0:MAXT for d in 0:MAXT
    if a + b ≤ MAXZ && 1 ≤ a + b + c + d])

(; model, spectral, meta) = build_model(pcase;
    master = [1], spectrum = eigenproblem)
(W, R) = parametrise(model, spectral, mset;
    resonance = ResonanceConfig(style = :complex_normal_form, tol = 0.05),
    conjugate_permutation = meta.conjugate_permutation)
05

Read the sensitivities

Rows of $\mathbf R$ that are linear in $z_1$ and linear in a parameter are exactly the frequency sensitivities — and they can be checked against an independent FEM identity.

examplemonomialcoefficientindependent check
07 arch$z_1\theta$+0.13164087 iarch-rise stiffening
04 beam$z_1\theta_1$−1.09479433 iFEM $\partial\omega/\partial\theta_1 = -1.094794$ (theory $-2\omega_0 = -1.097841$)
04 beam$z_1\theta_2$≈ 2·10⁻¹⁴ iFEM $\partial\omega/\partial\theta_2 = 0$ — the bending-mode field does not shift the frequency at first order

The ROM coefficient and the FEM sensitivity are computed along completely different paths, yet agree to every printed digit — a strong check that the parametric assembly and the cohomological solve are consistent.

Recap

  • Shape parameters become ROM coordinates through an additive reference map.
  • Each parameter scales an independent shape field — analytic or an FE field.
  • Truncation is per parameter (a box), not total degree.
  • Two physically different studies share one pipeline file; only config.jl differs.
  • Parametric sensitivities in the ROM match independent FEM identities.
