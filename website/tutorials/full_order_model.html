Building a full-order model

Literate script — standardized walkthrough ↗

In MORFE.jl full-order models have 3 components: the matrices of the linear terms, the nonlinear terms, and (optionally) a external system. This tutorial builds all three from scratch, draws what each one means and builds a model that holds them together.

The third panel is a term mixing state and external state, $F = k\,u\,(r_1+r_2)$ with $r_1+r_2 = 2\cos\Omega t$. Drag it to orbit.
Runs today — current code

Every line on this page comes from examples/internals/full_order_model. It needs no FEM backend and runs in a few seconds:

julia --project -e 'include("examples/internals/full_order_model/main.jl")'

What this tutorial covers

  • How a multiindex describes which derivatives go into a MultilinearMap.
  • Multiple kinds of ExternalSystem: harmonic, quasi-periodic, and nonlinear ones.
  • Assembling an NDOrderModel and integrating its forced response.

Mathematical formulation

MORFE considers $\mathrm{ORD}$-th order ODEs of the form

$$ \mathbf{B}_0\,\mathbf{u} + \mathbf{B}_1\,\dot{\mathbf{u}} + \mathbf{B}_{2} \, \ddot{\mathbf{u}} + \cdots = \sum_j \mathbf{T}_{j} (\underbrace{\mathbf{u}, \dotsc, \mathbf{u}}_{m_{j,0}}, \underbrace{\dot{\mathbf{u}}, \dotsc, \dot{\mathbf{u}}}_{m_{j,1}}, \dotsc, \underbrace{\mathbf{r}, \dotsc, \mathbf{r}}_{\widehat{m}_{j}}) \\[10pt] \dot{\mathbf{r}} = \mathbf{E}(\mathbf{r})$$

The matrices $\mathbf{B}_j$ describe the internal linear part; and the $\mathbf{T}_j$ express the remaining nonlinear and external terms as MultilinearMaps. The external state $\mathbf{r}$ satisfies its own autonomous dynamics $\dot{\mathbf{r}} = \mathbf{E}(\mathbf{r})$ and enters $\mathbf{T}_j$ to express non-autonomous terms. The first $m_{j,0}$ arguments of $\mathbf{T}_j$ have the zeroth derivative $\mathbf{u}$, the following $m_{j,1}$ arguments have the first derivative $\dot{\mathbf{u}}$, and so on. This defines the multiindex $(m_{j,0}, m_{j,1}, \dotsc, m_{j, \mathrm{ORD}-1})$. The external multiplicity $\widehat{m}_j$ counts how many copies of the external state $\mathbf{r}$ enter the term $\mathbf{T}_j$.

01

Multilinear terms

The $k$-th entry of multiindex defines $m_{j,k-1}$ which counts how many arguments of f! take the derivative $u^{(k-1)}$. The length of a multiindex is the order of the system. So for a second-order model, (3, 0) means f!(res, u, u, u) and (1, 1) means f!(res, u, u̇). 

using MORFE

# M ü + C u̇ + K u = F(u, u̇, r), so a *hardening* Duffing spring contributes F = −k₃ u³
duff!(res, u1, u2, u3) = (res .+= -6.0 .* u1 .* u2 .* u3)
drag!(res, v1, v2) = (res .+= -0.8 .* v1 .* v2)
mixed!(res, u, r) = (res .+= -1.5 .* u .* (r[1] + r[2]))

term_duff = MultilinearMap(duff!; multiindex = (3, 0), multiplicity_external = 0, fully_asymmetric = false)
term_drag = MultilinearMap(drag!; multiindex = (0, 2), multiplicity_external = 0)
term_mixed = MultilinearMap(mixed!; multiindex = (1, 0), multiplicity_external = 1)
multiindexthe arguments aredegree
(2, 0)$\mathbf{u}$, $\mathbf{u}$2
(3, 0)$\mathbf{u}$, $\mathbf{u}$, $\mathbf{u}$3
(0, 2)$\dot{\mathbf{u}}$, $\dot{\mathbf{u}}$2

The parametrisation method requires smooth maps

MORFE assumes MultilinearMap is linear in each argument; but cannot explicitly enforce this property. The user is responsible for ensuring multilinearity. For instance, MORFE cannot handle non-smooth functions like $F(u̇) = |u̇| u̇$ of Figure 1, panel 2.

02

External drivers

An ExternalSystem is an autonomous ODE $\dot{\mathbf{r}} = \mathbf{E}(\mathbf{r})$ whose state enters the model's multilinear terms as an extra argument. The classical case of harmomic forcing considers $\dot{r}_{1} = + i\Omega \, r_{1}$ and $\dot{r}_{2} = - i\Omega \, r_{2}$ with solutions $r_{1}(t) = r_{1,0} \, e^{ i\Omega t}$ and $r_{2}(t) = r_{2,0} \, e^{- i\Omega t}$. Fixing $r_{1,0} = r_{2,0} = 1$ and adding both states yields $r_1 + r_2 = 2 \cos(\Omega t)$. 

harmonic = ExternalSystem((im*Ω, -im*Ω)) # a circle
quasi = ExternalSystem((im*Ω₁, -im*Ω₁, im*Ω₂, -im*Ω₂)) # the closure is a torus

The tuple constructor covers the linear case. A driver may also be nonlinear — only its linear part has to be upper triangular — and that is what the third panel of the figure shows: a slow pair $(r_3, r_4)$ modulating a fast pair, and never the reverse. That one-way coupling is the triangular structure, made visible.

$$\begin{aligned} \dot r_1 &= i\Omega_1 r_1 + i c\, r_1 r_3 &\qquad \dot r_3 &= i\Omega_2 r_3 \\ \dot r_2 &= -i\Omega_1 r_2 - i c\, r_2 r_4 &\qquad \dot r_4 &= -i\Omega_2 r_4 \end{aligned}$$

A nonlinear driver is given as a polynomial rather than a tuple of eigenvalues, so the quadratic coefficients have somewhere to live. Most of that polynomial is zero, so the example writes only the terms that are not — the pair (i, exponent) => c saying that the monomial $r^{\alpha}$ contributes $c$ to $\dot r_i$: 

cascade = ExternalSystem(external_polynomial(4, 2,
    (1, (1, 0, 0, 0)) => im*Ω₁,     # ṙ₁ ← iΩ₁ r₁
    (2, (0, 1, 0, 0)) => -im*Ω₁,    # ṙ₂ ← −iΩ₁ r₂
    (3, (0, 0, 1, 0)) => im*Ω₂,     # ṙ₃ ← iΩ₂ r₃
    (4, (0, 0, 0, 1)) => -im*Ω₂,    # ṙ₄ ← −iΩ₂ r₄
    (1, (1, 0, 1, 0)) => im*c,      # ṙ₁ ← i c r₁r₃
    (2, (0, 1, 0, 1)) => -im*c))    # ṙ₂ ← −i c r₂r₄

Its linear part is diagonal — hence upper triangular — so the constructor accepts it, and the quadratic coefficients are left entirely free. Integrating the $r_3$ term gives $r_1 = \exp\!\big(i\Omega_1 t + (c/\Omega_2)(e^{i\Omega_2 t} - 1)\big)$, so $|r_1|$ swings between $e^{-2c/\Omega_2}$ and $1$: the modulation is sustained, not a transient that decays back onto the linear system's circle.

In all three cases the dynamics are stored as a polynomial, so solving one needs nothing more than evaluate and a standard solver; e.g. Runge–Kutta for time integration.

03

Lorenz system — rejected then repaired

$$\begin{aligned} \dot x &= \sigma (y - x) \\ \dot y &= x(\rho - z) - y \\ \dot z &= xy - \beta z \end{aligned}$$

There is one hard constraint: the linear part of an external system must be upper triangular. Its nonlinear part is unconstrained. Try the Lorenz system and the constructor refuses it: 

ArgumentError: The external system's linear matrix must be upper
triangular; non-zero entries below the diagonal at [(2, 1)].

The reason is causality. The cohomological equations are solved monomial by monomial in GrLex order, and the $|\beta| = 1$ lower-order coupling needs $W[\alpha - e_j + e_i]$ — a coefficient of the same total degree, which precedes $\alpha$ only when $i < j$. So the solver reads only the strictly upper triangle of $\Lambda$, and an entry below the diagonal would be discarded without trace. Reordering the variables does not help: both off-diagonal entries of Lorenz's $x$–$y$ block are non-zero, so one of them is always below the diagonal.

The repair is the one the error message suggests, applied to the full nonlinear system rather than to a linearisation. Two steps:

  • Shift the origin to a non-trivial fixed point $C_\pm = (\pm C, \pm C, \rho - 1)$ with $C = \sqrt{\beta(\rho-1)}$, which exists for $\rho > 1$. An ExternalSystem's polynomial carries no constant term, so the expansion has to be centred on an equilibrium.
  • Diagonalise the Jacobian there, $J = T \Lambda T^{-1}$. In modal coordinates $v = T^{-1}u$ the system becomes $\dot v = \Lambda v + T^{-1} Q(Tv, Tv)$, whose linear part is diagonal and therefore triangular.

The shift is exact and costs nothing, because Lorenz is quadratic: writing $u = (X, Y, Z) = r - C_+$, the constant terms cancel and the centred system is

$$\begin{aligned} \dot X &= \sigma (Y - X) \\ \dot Y &= X - Y - Z(X + C) \\ \dot Z &= C(X + Y) + XY - \beta Z \end{aligned}$$

— the same quadratic part $(0,\, -XZ,\, +XY)$ as the original, and a linear part that is exactly the Jacobian at $C_+$. Note the $(2,1)$ entry has become $1$ instead of $\rho$, but it is still not zero, which is why the shift alone does not make the matrix triangular and the diagonalisation is needed as well.

Diagonalising that Jacobian, $J = T \Lambda T^{-1}$, and setting $v = T^{-1}u$ gives the equations the ExternalSystem is actually built from:

$$\begin{aligned} \dot v_1 &= \lambda_1 v_1 &&+ \big[T^{-1} Q(Tv, Tv)\big]_1 \\ \dot v_2 &= \lambda_2 v_2 &&+ \big[T^{-1} Q(Tv, Tv)\big]_2 \\ \dot v_3 &= \overline{\lambda_2}\, v_3 &&+ \big[T^{-1} Q(Tv, Tv)\big]_3 \end{aligned}$$

with $Q(u, u) = (0,\, -XZ,\, XY)$ the unchanged quadratic part. The linear part is now $\Lambda = \mathrm{diag}(\lambda_1, \lambda_2, \overline{\lambda_2})$ — diagonal, hence upper triangular, hence accepted. The quadratic part is dense and stays completely unconstrained.

Stability is not what is needed here — only an equilibrium. At the familiar $\rho = 28$ the two non-trivial fixed points have already lost stability through a Hopf bifurcation at $\rho_H = \sigma(\sigma+\beta+3)/(\sigma-\beta-1) \approx 24.737$, and with no stable fixed point and no stable periodic orbit left, the chaotic attractor is what remains. The eigenvalues at $C_+$ are $-13.855$ and $0.094 \pm 10.194\,i$: an unstable focus, and perfectly admissible as a linear part because it is diagonal.

FIG · 03 The same orbit in two coordinate systems — switch tabs to compare. On the left the trajectory in phase space, which you can drag to orbit; on the right each coordinate against time, stacked and sharing one time axis. The modal tab is what the ExternalSystem actually integrates: $v_1$ decays on the fast real eigenvalue while $v_2$ and its conjugate spiral out of the unstable focus. The physical tab is the same data mapped back through $T$.

The orbit starts at $r_0 = (1, 1, 20)$ in physical coordinates — a point already inside the butterfly loops, so it is on the attractor from the first step and there is no transient to discard. The figure draws 90 s, over which the trajectory swaps wings some fifty times. Starting near $C_+$ instead would be a poor choice: it is an unstable focus with $\mathrm{Re}\,\lambda = 0.094$, so the orbit would spend tens of seconds spiralling slowly outwards and the picture would show that spiral rather than the attractor.

The script checks the change of coordinates instead of asserting it: the modal right-hand side mapped back through $T$ matches Lorenz's own at random points to $\sim10^{-13}$, and an orbit integrated as an ExternalSystem tracks a direct integration of Lorenz to $\sim10^{-11}$ over 5 s. That second check uses a deliberately short window — the attractor's largest Lyapunov exponent is $\approx 0.9\,\mathrm{s}^{-1}$, so two integrations of the same orbit separate like $e^{0.9t}$, and over 12 s round-off is already amplified by $5\times10^{4}$. Past that the comparison measures the Lyapunov exponent, not the coordinates.

Complex coordinates carry a reality condition

The modal coordinates are complex, but a physical state is not an arbitrary point of $\mathbb{C}^3$: $\lambda_1$ is real so $v_1$ is real, and $\lambda_3 = \overline{\lambda_2}$ so $v_3 = \overline{v_2}$. Those conditions cut out a real three-dimensional subspace which the exact flow preserves — but round-off does not, and here the unstable directions amplify the drift until the orbit leaves the attractor entirely: left alone, $\lVert v_3 - \overline{v_2}\rVert$ reaches $10^{2}$ by $t \approx 45$ s and $x$ wanders to $-79$, far outside Lorenz's $|x| \lesssim 18$. Projecting back onto the subspace after each step costs nothing, and it is the same reality condition MORFE's Realification module imposes on a parametrisation.

04

Assemble the model

An NDOrderModel takes the linear matrices as a tuple $(B_0, \ldots, B_{\mathrm{ORD}})$, the nonlinear terms as a tuple, and the external system. A forced Duffing oscillator is two terms — the hardening cubic from step 1 and a forcing term that reads the external state. 

forcing!(res, r) = (res .+= f * (r[1] + r[2]))
term_forcing = MultilinearMap(forcing!; multiindex = (0, 0), multiplicity_external = 1)

model = NDOrderModel((K, C, M), (term_hard, term_forcing), harmonic)

A, B = linear_first_order_matrices(model)   # companion pair for the eigensolver

A term that reads the external state needs a model that has one. Leave the ExternalSystem out and construction fails immediately, naming the term — rather than surviving to fail much later, during evaluation.

evaluate_nonlinear_terms! assembles $F$ at a given state, one degree at a time, which is all the right-hand side of a time integration needs. Driving the model with the harmonic system of step 2 gives the forced response:

FIG · 04 Damping pulls the orbit onto the periodic response — a closed loop, which the hardening cubic bends away from an ellipse. Twenty-five forcing periods are integrated; purple is the transient, red the final period, drawn as 1.01 of one so the curve laps itself and the loop closes visibly. It closes to 0.5% of its own diameter — the transient decays with a 25 s time constant, so after 121 s well under a percent of it survives. The nonlinear force at every step comes from evaluate_nonlinear_terms! on the model itself.

Recap

  • A multiindex is a calling convention: multiindex[k] slots take $x^{(k-1)}$, and its length is the system order.
  • Multilinear means linear in each slot separately — which rules out $|v|v$ and makes a quadratic drag even.
  • An ExternalSystem may be nonlinear; only its linear part must be upper triangular, and only because the GrLex solve reads nothing below the diagonal.
  • A system that fails that test can often be repaired: shift to an equilibrium, diagonalise the Jacobian. Lorenz becomes admissible, chaos and all.
  • NDOrderModel checks that a term reading the external state actually has one.
