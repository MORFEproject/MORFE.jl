Constructing MultiindexSets

Literate script — standardized walkthrough ↗

A MultiindexSet decides which monomials the DPIM solve computes. It is the one argument that separates an isotropic expansion from an anisotropic parametric ROM or a spectrally truncated one — and you can build it yourself.

FIG · 01 The three automatic generators. A multiindex $\alpha \in \mathbb N^N$ is the exponent vector of the monomial $z_1^{\alpha_1}\cdots z_N^{\alpha_N}$, so a set of them is a region of the integer lattice. Switch panels to compare the shapes.
Runs today — current code

Every line on this page comes from examples/internals/multiindex_sets. It needs no FEM backend and runs in a couple of seconds:

julia --project -e 'include("examples/internals/multiindex_sets/main.jl")'

What this tutorial demonstrates

  • The three automatic generators, and the graded-lexicographic order they produce.
  • Building the same sets by hand, straight from a vector of exponents.
  • Combining conditions — total degree in the master coordinates, a box in each parameter.
  • Removing multiindices with delete_multiindices and filter.
  • Bounding the superharmonics $s(\alpha) = \langle \lambda, \alpha\rangle$ by a spectral radius — and why that breaks the one invariant parametrise depends on.

Why the set matters

DPIM solves one cohomological problem per monomial. The set you supply is therefore the complete list of unknowns: a parametrisation $\mathbf W$ stores one coefficient column per member, and the reduced dynamics $\mathbf R$ does too. Doubling the set doubles the solve.

The exponents are kept sorted in graded-lexicographic (GrLex) order — total degree ascending, then lexicographic descending within a degree. That order is what makes the solve causal: by the time the solver reaches $\alpha$, every lower-degree coefficient it needs has already been computed.

01

Start from a constructor

Three functions cover the usual shapes. All three return a MultiindexSet already in GrLex order. 

using MORFE.Multiindices

total_deg = all_multiindices_up_to(2, 4; min_degree = 1)   # 1 ≤ |α| ≤ 4
exact_deg = multiindices_with_total_degree(2, 4)           # |α| = 4
box = filter(α -> sum(α) ≥ 1, all_multiindices_in_box([3, 3]))   # 0 ≤ αᵢ ≤ 3

The first is what parametrise builds when you pass no mset. Note min_degree = 1 on every one of them: the constant monomial is excluded, because the expansion is centred on the fixed point.

Position in the GrLex order is the column index used everywhere else in MORFE. find_in_set recovers it with a binary search bracketed to a single degree block, and returns nothing for a non-member: 

find_in_set(total_deg, [1, 1])   # 5
find_in_set(total_deg, [9, 9])   # nothing

# componentwise bound + a HALF-OPEN degree window: lower ≤ |α| < upper
indices_in_box_with_bounded_degree(total_deg, [2, 2], 1, 3)
# → [2, 3, 4, 5, 6]   i.e. [1,0] [0,1] [2,0] [1,1] [0,2]
02

Or hand over the exponents yourself

The generators are conveniences over one public constructor that takes the exponent vectors directly. Order does not matter — it sorts into GrLex and deduplicates for you. 

using StaticArrays: SVector

by_hand = MultiindexSet([SVector{2, Int}(a, b)
                        for a in 0:4 for b in 0:4 if 1 ≤ a + b ≤ 4])

by_hand == all_multiindices_up_to(2, 4; min_degree = 1)   # true

Two more spellings of the same thing — note the matrix form takes exponents as columns:

MultiindexSet([[1, 0], [0, 1], [1, 1]])   # Vector{Vector{Int}}
MultiindexSet([1 0 1; 0 1 1])           # nvars × nmonomials matrix
03

Combine conditions: total degree × box

This is the shape parametric ROMs need. The reduced coordinates split into master coordinates $z$, which deserve a shared total-degree budget, and parameter coordinates $\theta$, which deserve a budget each — order 4 in $z$ but only 2 in every $\theta$. The two conditions simply intersect. 

const MAXZ = 4   # total degree budget in the master coordinates
const MAXT = 2   # per-parameter budget in each θ

# route A — state both conditions in a comprehension
aniso_A = MultiindexSet([SVector{3, Int}(a, b, c)
                        for a in 0:MAXZ for b in 0:MAXZ for c in 0:MAXT
                        if a + b ≤ MAXZ && 1 ≤ a + b + c])

# route B — start from the enclosing box and narrow it
aniso_B = filter(α -> α[1] + α[2] ≤ MAXZ && sum(α) ≥ 1,
                 all_multiindices_in_box([MAXZ, MAXZ, MAXT]))

aniso_A == aniso_B   # true — 44 monomials, from a box of 75

Every button below acts on the same lattice — the box $[4,4,2]$ with the origin removed. The red ones are filters and intersect: switch two on and only the monomials satisfying both survive. The green ones add their monomials back on top of whatever the filters left. reset clears everything. What a condition excludes stays visible as a hollow marker, and the camera holds still across a toggle, so the shapes can be compared directly:

FIG · 02 One lattice, composable conditions — drag to orbit. Layers of $\alpha_3$ carry the Julia colours, so the extrusion is easy to read. Filters: total degree $|\alpha| \le 4$, the anisotropic cut $\alpha_1 + \alpha_2 \le 4$, a single variable $\alpha_1 \le 2$, and a full box $\alpha \le (2,2,1)$. The unions add a face of the lattice back — switch on the box filter and then a face to see monomials the box had cut reappear.

Switching on |α| ≤ 4 and α₁ + α₂ ≤ 4 together is the point of this section: the anisotropic cut is not an isotropic expansion of the same order. $|\alpha| \le 4$ in three variables allows $\alpha_3 = 3$ or $4$ while forbidding the total degrees 5 and 6 that the anisotropic set keeps.

The origin is never a member

Every set on this page satisfies $|\alpha| \ge 1$. DPIM expands around a fixed point, so MORFE.jl skips the constant monomial — build with min_degree = 1, or filter with sum(α) ≥ 1.

04

Remove multiindices

delete_multiindices returns a new set. There is no in-place variant, so a set already handed to a parametrisation can never be mutated underneath it. 

S = all_multiindices_up_to(2, 3; min_degree = 1)

# by explicit exponent — one, a list of them, or another set
delete_multiindices(S, [[3, 0], [0, 3]])
delete_multiindices(S, [1, 1])
delete_multiindices(S, all_multiindices_up_to(2, 1; min_degree = 1))

# by predicate — and `filter` keeps exactly what this drops
odd = delete_multiindices(α -> iseven(sum(α)), S)
even = filter(α -> iseven(sum(α)), S)

length(odd) + length(even) == length(S)   # true — they partition S

Exponents that are not members are ignored, as with setdiff. Deletion cannot reorder a sorted list, so the result skips the re-sort — but the degree boundary table is rebuilt, and lookups stay correct even when an entire degree disappears: 

gapped = delete_multiindices(α -> sum(α) == 2, S)

find_in_set(gapped, [3, 0])   # 4
find_in_set(gapped, [1, 1])   # nothing
FIG · 03 Deletion is non-mutating: every panel is a new set derived from the first, with what was removed drawn hollow.
05

Bound the superharmonics by a spectral radius

Every monomial carries a superharmonic $s(\alpha) = \langle \lambda, \alpha\rangle$ — the eigenvalue of the linear part at which its forced response sits. You get it by adding the eigenvalues head to tail, $\alpha_k$ copies of $\lambda_k$. MORFE already computes it for resonance detection: $\alpha$ is resonant with master mode $r$ when $|\lambda_r - s(\alpha)| < \texttt{tol}$.

The same quantity supports a truncation no degree or box bound can express — keep only the monomials whose response lands inside a band $|s(\alpha)| < R$ of the spectrum. Take a damped spectrum: one oscillatory conjugate pair and one real decaying mode. 

λ = [-1 + 2im, -1 - 2im, -1.0 + 0im]
superharmonic(α) = sum(λ .* α)   # s(α) = ⟨λ, α⟩

full = all_multiindices_up_to(3, 4; min_degree = 1)
R = 4.0

band = filter(α -> abs(superharmonic(α)) < R, full)
# 34 monomials → 13
FIG · 04 Left: the multiindex lattice. Right: the corresponding complex superharmonics, with $|s| = 4$ dashed. Hover a monomial and the arrows add $\alpha_1$ copies of $\lambda_1$, $\alpha_2$ of $\lambda_2$ and $\alpha_3$ of $\lambda_3$ to reach it. The yellow rings are the two divisors that fall outside the band — the ones step 06 has to add back.

Two things the right-hand panel makes obvious. Every superharmonic has $\operatorname{Re} s < 0$ — the whole right half-plane is empty, because every mode is damped. And there are only nine distinct points for thirteen monomials: superharmonics collide. $(1,1,0)$ and $(0,0,2)$ both land on $-2$; $(2,1,0)$ and $(1,0,2)$ both land on $-3+2i$ by different routes. Collisions are the whole reason resonance detection exists.

06

The contract, and how it is enforced

A spectral cut is not downward closed: it can keep $\alpha$ while dropping a divisor of $\alpha$. The graded solve reads $\mathbf W[\alpha - e_i]$ while working on $\alpha$, so a missing divisor would be silently read as zero. That is why the set is checked before anything is solved. 

is_downward_closed(band)   # false
# [2,1,0] is kept (|s| = 3.606), but its divisor [2,0,0] has |s| = 4.472 ≥ R
# [1,2,0] is kept (|s| = 3.606), but its divisor [0,2,0] has |s| = 4.472 ≥ R

The fix is to take the downward closure — add back every divisor of every member. The result is legal, and still far smaller than the full expansion: 

function downward_closure(S::MultiindexSet{N}) where {N}
    closed = Set{SVector{N, Int}}()
    for α in S.exponents
        for idx in CartesianIndices(ntuple(i -> 0:α[i], N))
            push!(closed, SVector{N, Int}(Tuple(idx)))
        end
    end
    delete!(closed, zero(SVector{N, Int}))   # DPIM needs min_degree ≥ 1
    return MultiindexSet(collect(closed))
end

is_downward_closed(downward_closure(band))   # true — 15 monomials, vs 34
# the closure added exactly [2,0,0] and [0,2,0]

The full contract for a custom mset:

ClauseWhyChecked by parametrise?
NVAR = ROM + N_EXTone coordinate per reduced variableyes
min total degree ≥ 1the expansion is centred on the fixed pointyes
every unit multiindexthe linear part is initialised from the eigenvectorsyes
downward closedthe graded solve reads $\mathbf W[\alpha - e_i]$yes
closed under conjugationonly when a conjugate permutation is usedyes

All five are enforced by validate_multiindex_set, which parametrise and solve_cohomological_problem both run before solving. It takes no model, so you can check a set the moment you build it, and it names the offending exponent rather than just refusing: 

validate_multiindex_set(band, 3, 3)
# ArgumentError: custom mset is not downward closed: [2, 1, 0] is a member
# but its divisor [2, 0, 0] is not. The graded solve reads W[α - β + eᵢ] and
# factorises α over members of mset, so a missing divisor is read as zero
# and silently corrupts the right-hand side.
Why these two used to be your problem

The two closure clauses fail differently. A missing divisor is read as zero and silently corrupts the right-hand side — wrong numbers, no error. A missing conjugate partner keeps the answer correct but makes the solve fall back to solving that monomial directly, so you lose the pairing optimisation and the result no longer carries the conjugate structure the permutation asserts. Both are now rejected up front; pass validate_mset = false to skip the check if you have already done it yourself.

Then hand it over:

W, R = parametrise(model, order, eigenproblem; mset = band_closed)

Recap

  • Generators cover the simplex and the box; the plain constructor covers everything else.
  • filter and delete_multiindices are complements, both non-mutating, both preserving GrLex order and the degree boundary table.
  • Anisotropy is just an intersection of conditions — total degree in $z$, a box in each $\theta$.
  • A spectral bound is the one truncation that uses the eigenvalues — and the one whose downward closure you must take, because $|s|$ is not monotone under divisibility. parametrise will reject it otherwise.
  • The contract is enforced, not assumed: validate_multiindex_set checks all five clauses and names the exponent that breaks one.
