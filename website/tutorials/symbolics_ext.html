Symbolic full-order model

Literate script — standardized walkthrough ↗

This tutorial is an extension of Tutorial "Building a full-oder model" introducing a new way to define the full order model via writing the model as an ODE in a symbolic way using Symbolics.jl.

The ODE is defined either as an expression equal to zero or as a function of the right hand side. Only autonomous and polynomial ODEs are allowed.

This is escpacially useful for defining the ExternalSystem that describes forcing and parametrisation.

The main functions are:

  • model_from_symbolics.
  • externalsystem_from_symbolics.
It's a package extension

MORFESymbolicsExt is a weak-dependency extension of MORFE: it loads automatically the moment both MORFE and Symbolics are loaded in the same session. You never import it by name — just

using MORFE, Symbolics

What this tutorial demonstrates

  • Writing an ODE with Symbolics.jl variables and turning it into an NthOrderModel with model_from_symbolics.
  • Defining a standalone ExternalSystem with externalsystem_from_symbolics.
  • Coupling the two: a model whose right-hand side reads the external state, built in one call.
  • The DifferentialEquations.jl-style convenience layer, that allows the definition of the ODE as a function f!(du, u, p, t).

General usage

As in Tutorial "Building a full-order model" we consider a $\mathrm{ORD}$-th order ODEs of the form

$$ \mathbf{B}_0\,\mathbf{u} + \mathbf{B}_1\,\dot{\mathbf{u}} + \mathbf{B}_{2} \, \ddot{\mathbf{u}} + \cdots = \sum_j \mathbf{T}_{j} (\underbrace{\mathbf{u}, \dotsc, \mathbf{u}}_{m_{j,0}}, \underbrace{\dot{\mathbf{u}}, \dotsc, \dot{\mathbf{u}}}_{m_{j,1}}, \dotsc, \underbrace{\mathbf{r}, \dotsc, \mathbf{r}}_{\widehat{m}_{j}}) \\[10pt] \dot{\mathbf{r}} = \mathbf{E}(\mathbf{r})$$

MathCodeMeaning
$\mathbf u, \dot{\mathbf u}, \ddot{\mathbf u}, \dots$ groups = (u, du, ddu, ...) one Symbolics vector per derivative order, ascending
$\mathbf B_0\mathbf u + \mathbf B_1\dot{\mathbf u} + \mathbf B_2\ddot{\mathbf u} + \cdots$ (extracted automatically from exprs) Jacobian of exprs w.r.t. each group, evaluated at the origin
$\mathbf T_j(\dots)$ (extracted automatically from exprs) what's left of exprs after the linear part — split by monomial into one MultilinearMap per $j$
$\mathbf r$ ext_var external state, declared with its own @variables
$\dot{\mathbf r} = \mathbf E(\mathbf r)$ ext_exprs autonomous polynomial right-hand side, passed alongside ext_var

ExternalSystem

The right-hand-side $\mathbf{E}(\mathbf{r})$ of a ExternalSystem must be a polynomial function in $\mathbf{r}\in\mathbb{R}^R$ and is not allowed to be time-dependent. Also zero must be a equilibrium point. So it should hold: $\mathbf{E}(\mathbf{0})=\mathbf{0}$.

There are three different options too define a ExternalSystem symbolic. The first one is to define the right-hand-side $\mathbf{E}(\mathbf{r})$ as an expression. 

# R external states, autonomous dynamics ṙ = E(r)
@variables r[1:R]
r = collect(r)

ext_exprs = [ # E(r) — polynomial, autonomous
    #   ...
]

external_1 = externalsystem_from_symbolics(ext_exprs, r)

The other options are to define a DifferentialEquations.jl-shaped function, by using either a return function g or a in place function g!:

function g(r, params, t)
    dr = similar(r)
    dr[1] = # ...
    # ...
    dr[R] = # ...
    return dr
end
external_2 = externalsystem_from_symbolics(g, R; p = params)


function g!(dr, r, params, t)
    dr[1] = # ...
    # ...
    dr[R] = # ...
end
external_3 = externalsystem_from_symbolics(g!, R; p = params)

Full model

A code, for a system of order $N$ in $n$ degrees of freedom, coupled to $R$ external states would look like this: 

# N+1 derivative groups (u, u̇, ü, …), n dof each — extend the list for N > 2
@variables u[1:n] du[1:n] ddu[1:n]
u, du, ddu = collect(u), collect(du), collect(ddu)
groups = (u, du, ddu)   # (u, u̇, ü, …) — ascending order

# R external states, autonomous dynamics ṙ = E(r)
@variables r[1:R]
r = collect(r)

exprs     = [ # B₀u + B₁u̇ + B₂ü + ⋯ − Σⱼ Tⱼ(u,…,u,u̇,…,u̇,…,r,…,r) , written as "= 0"
    #   ...
]
ext_exprs = [ # E(r) — polynomial, autonomous
    #   ...
]

model = model_from_symbolics(exprs, groups, r, ext_exprs)

The external arguments r and ext_exprs (and call model_from_symbolics(exprs, groups) instead) can be dropped for a purely autonomous, unforced system — the four-argument form is only needed once an external state actually appears on the right-hand side.

Both constructors also accept a DifferentialEquations.jl-shaped function directly — no Symbolics variables to declare by hand, no groups tuple to build. For a plain order-$N$, $n$-dof model, arguments run from the highest derivative down to $\mathbf u$ itself: 

function f!(dᴺu, #=…=# ddu, du, u, params, t)
    dᴺu[1] = # ...
    # ...
end
function g!(dr, r, params_ext, t)
    dr[1] = # ...
    # ...
end

model = model_from_symbolics(f!, N, n, g!, R; p = params, p_ext = params_ext)

Full model: Two-mass oscillator

We consider the two-degree-of-freedom nonlinear oscillator introduced by Shaw and Pierre. The system consists of two coupled masses with linear stiffness and damping, while the first mass has an additional cubic restoring force:

$$ \ddot u_1 + c\,\dot u_1 - c\,\dot u_2 + (1+k)\,u_1 - k\,u_2 + g\,u_1^3 - 2\cos(\Omega\,t)= 0\\ \quad\quad\,\ddot u_2 - c\,\dot u_1 + 2c\dot u_2 -k\,u_1 + (1+k)\,u_2 = 0 $$

Later a harmonic force will be added to the first equation. Written as $\text{expr} = 0$, with $\mathbf u = (u_1,u_2)$, this is exactly the input model_from_symbolics expects: a vector of expressions and the tuple of derivative groups $(\mathbf u, \dot{\mathbf u}, \ddot{\mathbf u})$ that appear in them.

01

Definition of the model using symbolic variables without forcing

We begin with the unforced/autonomous equation, so we drop the $-2\cos(\Omega t)$. We need to declare one Symbolics.jl vector per derivative order, write the equations of motion as expressions that equal zero, and hand both to the function model_from_symbolics. 

@variables u[1:2] du[1:2] ddu[1:2]
u, du, ddu = collect(u), collect(du), collect(ddu)

k, g, c = 1.0, 6.0, 0.1

exprs = [
    ddu[1] + c*du[1] - c*du[2] + (1 + k)*u[1] - k*u[2] + g*u[1]^3,
    ddu[2] - c*du[1] + 2*c*du[2] - k*u[1] + (1 + k)*u[2],
]

groups = (u, du, ddu)   # ascending order: (u, u̇, ü)

model = model_from_symbolics(exprs, groups)

The tuple groups is supposed to be ordered low-to-high: the last entry is the derivative the equation is solved for.

Internally, extract_linear_matrices takes the Jacobian of exprs with respect to each group and evaluates it at the origin to get the linear matrices $\mathbf B_0, \mathbf B_1, \mathbf B_2$; everything left over after subtracting the linear part is split into monomials, grouped by multidegree, and turned into one MultilinearMap per group — here just the cubic terms $g\,u_1^3$:

02

Define the model using symbolic variables with forcing

As in "Building a full-order model" explained we can subtitute the non-autonomous term $-2\cos(\Omega t)$ by $-r_1-r_2$ with $\dot r_1=i\Omega r_1$ and $\dot r_2=i\Omega r_2$. So we need to add this new ODEs as an external system. 

@variables u[1:2] du[1:2] ddu[1:2] r[1:2]
u, du, ddu = collect(u), collect(du), collect(ddu)

k, g, c = 1.0, 6.0, 0.1

exprs = [
    ddu[1] + c*du[1] - c*du[2] + (1 + k)*u[1] - k*u[2] + g*u[1]^3 - r[1] -r[2],
    ddu[2] - c*du[1] + 2*c*du[2] - k*u[1] + (1 + k)*u[2],
]

ext_exprs = [
    im*Ω * r[1],
    -im*Ω  * r[2],
]

groups = (u, du, ddu)   # ascending order: (u, u̇, ü)
ext_var = collect(r)
model = model_from_symbolics(exprs, groups, ext_var, ext_exprs)

Examples for ExternalSystem

In practice, the full-order side of a model rarely comes from a symbolic definition — it comes out of a FEM code, as mass, damping, and stiffness matrices plus a nonlinear assembly routine. Where the symbolic interface earns its keep is the ExternalSystem: the moment a forcing term, a bifurcation parameter, or any other external state enters the picture, it has to be tracked through the whole reduced-order-model construction — and externalsystem_from_symbolics is an easy way to define it.

01

Harmonic excitation

In "Building a full-oder model" the harmonic driver $\dot r_1 = i\Omega r_1,\ \dot r_2 = -i\Omega r_2$ is directly defined from its eigenvalues: ExternalSystem((im*Ω, -im*Ω)). Written symbolically instead, the same driver is just its own right-hand side: 

@variables r[1:2]
r = collect(r)
Ω = 1.3

ext_exprs = [im*Ω*r[1], -im*Ω*r[2]]
harmonic = externalsystem_from_symbolics(ext_exprs, r)   # same object as ExternalSystem((im*Ω, -im*Ω))

Unlike the eigenvalue-tuple constructor, ext_exprs does not have to be linear — externalsystem_from_symbolics accepts any polynomial right-hand side, the same way ExternalSystem(linear_polynomial(A)) or the chaotic Lorenz driver in full_order_model.html do. The one constraint is that it must be autonomous: $t$ itself may never appear, only the states $\mathbf r$ — that is the whole point of routing time-dependence through an external system rather than writing it directly into the model.

02

Quasi-periodic and multiharmonic drivers

A pair of incommensurate frequencies closes onto a torus rather than a circle — still linear, still diagonal, just twice as many states. Two independent harmonic pairs, written the same way as Step 01: 

@variables r[1:4]
r = collect(r)
Ω1, Ω2 = 1.0, sqrt(2)   # incommensurate
 
ext_exprs = [
    im*Ω1*r[1], -im*Ω1*r[2],
    im*Ω2*r[3], -im*Ω2*r[4],
]
quasi = externalsystem_from_symbolics(ext_exprs, r)   # same object as ExternalSystem((im*Ω1,-im*Ω1,im*Ω2,-im*Ω2))

The eigenvalue-tuple constructor only reaches diagonal systems, though. Suppose the two signals you actually want are $r_1 = -\cos\Omega t$ and $r_2 = 0.03\sin\Omega t - \cos 4\Omega t$ — not diagonal in the obvious basis. Introducing auxiliary states $r_3=\sin\Omega t$, $r_4=\sin 4\Omega t$ to close this as a first-order linear system gives $\dot{\mathbf r} = \mathbf A\mathbf r$ with (see "Building a full-order model", Step 02 for the derivation): 

Ω = 1.3
@variables r[1:4]
r = collect(r)
 
ext_exprs = [
    Ω*r[3],
    -0.03*Ω*r[1] + 4*Ω*r[4],
    -Ω*r[1],
    -4*Ω*r[2] + 0.12*Ω*r[3],
]
multiharmonic = externalsystem_from_symbolics(ext_exprs, r)   # same object as ExternalSystem(linear_polynomial(A))

externalsystem_from_symbolics extracts the same linear matrix $\mathbf A$ from these expressions that you'd build by hand — it isn't upper triangular here, so MORFE re-bases it internally and reports the change of coordinates, exactly as it does for the matrix form. See "Building a full-order model", Step 02 for that message and the resulting phase portraits.

03

Chaotic nonlinear excitation

A nonlinear driver works the same way — as long as it satisfies the same conditions as everything else on this page: polynomial, equilibrium at the origin. The Lorenz system has three equilibria, none at the origin — so "Building a full-order model", Step 03 shifts coordinates to the nontrivial equilibrium $C_+=(C,C,\rho-1)$, $C=\sqrt{\beta(\rho-1)}$, before defining it:

$$ \dot X = \sigma(Y-X), \qquad \dot Y = X - Y - Z(X+C), \qquad \dot Z = C(X+Y)+XY-\beta Z $$

Written symbolically, that shift is just the coordinates you declare — the check that would have caught the unshifted system (nonzero constant term at the origin) is the same check_constant_terms from Step 05: 

σ, ρ, β = 10.0, 28.0, 8/3
C = sqrt(β*(ρ-1))
 
@variables X Y Z
r = [X, Y, Z]
 
ext_exprs = [
    σ*(Y-X),
    X - Y - Z*(X+C),
    C*(X+Y) + X*Y - β*Z,
]
lorenz = externalsystem_from_symbolics(ext_exprs, r)

Recap

  • model_from_symbolics(exprs, groups) replaces hand-built B_k matrices and MultilinearMap closures with a vector of expressions.
  • externalsystem_from_symbolics(exprs, var) builds an ExternalSystem from its own autonomous ODE — linear or not.
  • model_from_symbolics(exprs, groups, ext_var, ext_exprs) couples the two in one call, building the ExternalSystem internally.
  • Both constructors have a DifferentialEquations.jl-shaped convenience method, f!(du, u, p, t)-style — but only for the two standalone cases, not the coupled one.
