Kármán vortex street

This tutorial teaches the complete MORFE workflow on the 57 860-DOF incompressible flow past a cylinder.

FIG · 01 Vorticity of base flow + oscillating Hopf mode, animated on the actual FE mesh from the VTK output. The steady wake destabilises at Re_c ≈ 49 and the pattern travels downstream at the shedding frequency $\omega_0 \approx 16.86$ rad/s.
Runs today — current API

All code on this page is the real, shipped implementation in examples/05_karman_vortex_street. Three commands reproduce every number and figure.

What this tutorial demonstrates

  • Defining up the full-order model for MORFE from your own FEM code.
  • Centering the analysis on a steady state — here Newton–Raphson solves the base flow.
  • Defining nonlinearities: a FEM-assembled quadratic term via the FEMMultilinearMap interface, matrix- and vector-based terms via MultilinearMap closures, and a bifurcation parameter via ExternalSystem.
  • Selecting master modes and building the resonance set.
  • Running solve_cohomological_problem and using the outputs $(W, R)$.
Prerequisites

Julia ≥ 1.10 (the example instantiates its own environment, Gmsh included) and, for the post-processing step only, Python 3 with numpy + matplotlib.

git clone https://github.com/MORFEproject/MORFE.jl.git
cd MORFE.jl/examples/05_karman_vortex_street
julia --project=. main.jl        # the whole reduction, ≈ 7 min

Defining the full-order model

The cylinder flow is a first-order ($N=1$) ODE: linearising the incompressible Navier–Stokes equations about the steady base flow and subtracting it leaves the perturbation $\mathbf x = [u';p']$ at the origin, obeying a differential–algebraic system — pressure carries no time derivative, so the mass matrix $\mathbf{B_1}$ is singular.

$$\mathbf B_1\,\dot{\mathbf x} + \mathbf B_0\,\mathbf x = \mathbf F(\mathbf x,\mathbf r) = \underbrace{\mathbf T_1(\mathbf x,\mathbf x)}_{\text{convection}} \,\, + \! \underbrace{\mathbf T_2(\mathbf x,\mathbf r)}_{\text{viscous coupling}} + \!\! \underbrace{\mathbf T_3(\mathbf r)}_{\text{base-flow forcing}}$$

The right-hand side is a sum of multilinear maps $\mathbf T_j$, each linear in every argument. A term's signature is simply how many copies of the state $\mathbf x$ and of the external variable $\mathbf r$ it consumes — that is all MORFE needs to place it in the expansion. For this model:

  • $\mathbf B_1$ — velocity mass matrix; singular (no pressure time derivative), so this is a descriptor system that MORFE solves in native form.
  • $\mathbf B_0$ — Jacobian of the steady Navier–Stokes operator at the base flow: viscous, base-flow convection, and pressure/continuity coupling.
  • $\mathbf T_1(\mathbf x,\mathbf x) = -(u'\!\cdot\!\nabla)u'$ — two state arguments, no external one: the single quadratic nonlinearity of incompressible flow.
  • $\mathbf T_2(\mathbf x,\mathbf r) = -D\,\mathbf K_{\mathrm{visc}}\,u'\,r$ — one state and one external argument.
  • $\mathbf T_3(\mathbf r) = -D\,\mathbf K_{\mathrm{visc}}\,u_0\,r$ — no state argument, one external one: a constant vector scaled by $r$.
  • $\mathbf r = \eta' = 1/\mathrm{Re} - 1/\mathrm{Re}_0$, an external state with $\dot{\mathbf r} = 0$ (a frozen parameter). Because $\nu = D/\mathrm{Re}$ enters linearly, $\mathbf B_0$ holds the operator at $\mathrm{Re}_0$ while $\mathbf T_2$ and $\mathbf T_3$ carry the departure from it — so a single reduction is parametric in Re.

MORFE interacts with the model only through the matrices $\mathbf B_k$, the callbacks that evaluate the maps $\mathbf T_j$, and the eigenvectors of the linearised operator; it imposes no mesh or element format. Any order-$N$ system with a polynomial right-hand side fits this template.

01

Center the analysis on the steady flow (Newton–Raphson)

DPIM expands an invariant manifold around a fixed point. For a fluid that fixed point is the steady base flow $u_0$, which must be computed first — here by a Newton–Raphson iteration on the stationary Navier–Stokes residual (quadratic convergence, ‖R‖ → 10⁻¹⁰ in six iterations). The linear operators are then the Jacobian at that point: 

# stage 3 — Newton–Raphson for the base flow u₀ at Re₀ (the expansion point)
(_, _, s₀_full) = solve_steady_state(fom; Re0 = Re₀)

# stage 4 — linearise around u₀:  B₁ ṡ + B₀ s = F(s, η′)
(B₀, B₁) = assemble_linear_operators(s₀_full, fom; Re0 = Re₀)

Both functions are plain Ferrite assembly code from the example (solver/steady_state.jl, fem/linear_operators.jl) — this part is yours, in whatever FEM library you use. MORFE operates only on the sparse matrices $\mathbf B_0, \mathbf B_1$ once they exist.

Why the fixed point matters

Every coefficient MORFE computes is an expansion around $u_0$. If the Newton solve is not converged, the "linear" part of the dynamics silently contains residual forcing and every higher-order coefficient inherits the error. Check ‖R(u₀)‖ before proceeding.

02

Declare the multilinear maps

The three terms of $\mathbf F$ from the previous section — $\mathbf T_1$, $\mathbf T_2$, $\mathbf T_3$ — are declared one by one. Each states its signature: the number of state arguments it consumes (multiindex, one entry per derivative order — here just $m_{j,0}$) and the number of external arguments (multiplicity_external, the count $\widehat m_j$). MORFE needs nothing more than a callback that evaluates the map on the supplied arguments, and it exploits symmetry in repeated arguments automatically.

(a) $\mathbf T_1$ — quadratic convection

($-(u'\!\cdot\!\nabla)u'$; multiindex=(2,), multiplicity_external=0)

It is evaluated by element-level callbacks rather than stored as a dense, high-dimensional tensor: the example subtypes FEMMultilinearMap, and MORFE calls it with the manifold columns it needs, batched over the mesh:

struct FluidConvection{DH, CV} <: MORFE.FEMMultilinearMap{1}
    # … FEM handles and buffers …
    multiindex::NTuple{1, Int}      # (2,)  — quadratic in the state
    multiplicity_external::Int     # 0    — no η′ factor
end

# the physics is contained in a single quadrature-point callback:
function MORFE.accumulate_qp!(Fe, (qp1, qp2), mult, _, q, dΩ, t::FluidConvection)
    conv = -0.5 * (qp2.grad ⋅ qp1.val + qp1.grad ⋅ qp2.val)   # −½[(u₁·∇)u₂+(u₂·∇)u₁]
    for i in 1:t.n_vel_dofs_per_cell
        Fe[t.dof_range_u[i]] += mult * dΩ * (shape_value(t.cv_vel, q, i) ⋅ conv)
    end
end

(b) $\mathbf T_2$ — viscous parameter coupling

($-D\,\eta'\, \mathbf K_{\mathrm{visc}}\, u'$; multiindex=(1,), multiplicity_external=1)

A pre-assembled sparse matrix wrapped in a closure — one state argument, one external argument:

g₁!(acc, s, r) = mul!(acc, K_visc, s, r[1], one(eltype(acc)))
g₁ = MultilinearMap(g₁!, (1,), 1)          # multiindex (1,), one η′ factor

(c) $\mathbf T_3$ — base-flow forcing

($-D\,\eta'\, \mathbf K_{\mathrm{visc}}\, u_0$; multiindex=(0,), multiplicity_external=1)

A fixed vector — no state argument, one external argument. It aligns the $\eta'$-direction of the manifold with the family of steady states at neighbouring Re:

h₀!(acc, r) = axpy!(eltype(acc)(r[1]), h₀_vec, acc)
h₀ = MultilinearMap(h₀!, (0,), 1)

Finally the external state $\mathbf r = \eta'$ is an ExternalSystem with a single eigenvalue 0 ($\dot\eta' = 0$), and the maps are collected into the model:

ext_sys = ExternalSystem((0.0 + 0.0im,))
model = NDOrderModel((B₀, B₁), (convection, g₁, h₀), ext_sys)
03

Choose the master modes

The master modes span the tangent space of the manifold. Here they are the Hopf pair — the least-damped complex-conjugate eigenpair of the generalised problem $-\mathbf B_0\, y = \lambda\, \mathbf B_1\, y$, found by shift-invert ARPACK. MORFE also needs the left eigenvectors, which enter the solvability conditions of the reduced dynamics: 

(λs, Φ, Ψ, …) = solve_hopf_eigenproblem(-B₀, B₁; nev = 40, …)
#   Selected Hopf mode:  λ₁ = +0.004028 +16.859169·i   (and λ₂ = conj(λ₁))

At Re₀ = 49.03 the pair sits just right of the imaginary axis — the base flow is marginally unstable, shedding at $\omega_0 = 16.86$ rad/s (St ≈ 0.27). Together with $\eta'$, the reduced coordinates are $(z_1, \bar z_1, \eta')$: a 2-real-dimensional oscillator plus one parameter direction.

04

Multi-indices and the resonance set

The parametrisation is a polynomial in the reduced coordinates. You choose which monomials exist (everything up to a total degree) and which of them stay in the reduced dynamics (the style of the parametrisation). The normal-form style keeps only near-resonant monomials — for a Hopf pair those are $z_1 |z_1|^{2k} \eta'^{\,j}$: 

mset = all_multiindices_up_to(3, 9; min_degree = 1)   # z₁^a z̄₁^b η′^c, a+b+c ≤ 9 → 219 monomials

resonance_set = resonance_set_from_complex_normal_form_style(
    mset, [im*ω₀, -im*ω₀], 0.05ω₀;
    external_eigenvalues = [0.0 + 0.0im])

Because the FOM matrices are real and the two master modes are conjugates, MORFE can skip half of the work: the conjugate_permutation below declares that mode 2 is the conjugate of mode 1 and that $\eta'$ is self-conjugate (real).

05

Solve the cohomological equations

W, R = solve_cohomological_problem(
    model, mset, master_eigenvalues,
    master_modes .* 1e-2, left_eigenmodes .* 1e-2,   # coordinate rescale for conditioning
    resonance_set;
    conjugate_permutation = [2, 1, 3])

This is the core of MORFE: it walks the 219 monomials in graded order and solves a small bordered linear system per monomial (≈ 6 min here). It returns the two objects of the invariance equation:

  • W — the manifold map: coefficients $W_\alpha \in \mathbb C^{57860}$ such that the full state is $x = \sum_\alpha W_\alpha\, z^\alpha$. Access them via MORFE.ParametrisationMethod.coefficients(W).
  • R — the reduced dynamics $\dot z = R(z)$ on the manifold, over the coordinates $z = (z_1, \bar z_1, \eta')$. Only the first row must be solved numerically: row 2 is its complex conjugate ($z_2 = \bar z_1$) and row 3 is the frozen parameter ($\dot\eta' = 0$). With the normal-form style, only resonant monomials survive, so the first row reads
$$\dot z_1 = (0.0040 + 16.86\,i)\,z_1 + (-212.0 - 59.1\,i)\,z_1\eta' + (-0.111 + 0.071\,i)\,z_1|z_1|^2 + (2981 + 95\,i)\,z_1\eta'^2 + \cdots$$

read directly from reduced_dynamics.txt (each row is one monomial [z₁-pow, z̄₁-pow, η′-pow] and its complex coefficient):

ż₁ = R₁(z₁, z̄₁, η′) — nonzero monomials  [z₁-pow, z̄₁-pow, η′-pow]:
  [1, 0, 0]      : +4.0284400035e-03 +1.6859169021e+01·i     # λ₁ = growth rate + shedding freq.
  [1, 0, 1]      : -2.1200793228e+02 -5.9107701234e+01·i     # sensitivity to Re
  [2, 1, 0]      : -1.1101108534e-01 +7.0650764135e-02·i     # cubic saturation
  [1, 0, 2]      : +2.9810858630e+03 +9.5235017009e+01·i
  ...

Three coefficients carry the physics. The linear one is the eigenvalue $\lambda_1$: its real part is the growth rate, its imaginary part the shedding frequency $\omega_0$. The $z_1\eta'$ coefficient is the sensitivity to Re; setting the growth rate to zero, $\mathrm{Re}(\lambda_1) + \mathrm{Re}(c_{101})\,\eta' = 0$, places the bifurcation at $\mathrm{Re}_c \approx 48.98$. The real part of the $z_1|z_1|^2$ coefficient is negative, so the cubic term saturates the amplitude — the Hopf bifurcation is supercritical and a stable limit cycle grows continuously from $\mathrm{Re}_c$.

06

Use the ROM: branch, observables, order convergence

With normal-form style the ROM limit cycle is exactly a circle $z_1 = \rho e^{i\Omega t}$, so the whole bifurcation diagram is the 2×2 continuation problem $\mathrm{Re}[R_1(\rho,\rho,\eta')] = 0$ — solved in seconds (solve_rom.jl). Physical observables are projections of $W$: the lift is the polynomial $L_\alpha = l^{\!\top} W_\alpha$ and the kinetic energy needs only the small Gram matrix $\mathbf G = W_{\mathrm{vel}}^{\!\top} \mathbf M_{\mathrm{vel}} W_{\mathrm{vel}}/|\Omega|$ — no full-order data is needed downstream: 

julia --project=. solve_rom.jl      # limit-cycle branch per truncation order
python3 compare_orders.py           # lift & ⟨TKE⟩ vs Re, one curve per order
One run = every order (exactly)

The cohomological solve is graded: degree-$N$ coefficients never depend on degrees $> N$. Zeroing all monomials above degree $N$ in the order-9 $(W,R)$ therefore gives the order-$N$ ROM bit-exactly (verified against separate runs). The order-convergence study below costs nothing beyond the single order-9 run.

FIG · 02 Maximum lift along the limit cycle vs Re, per truncation order — hover for values, click the legend to toggle orders, or arm the toolbar tools to zoom/pan. The horizontal line is the steady base flow (solid = stable, dashed = unstable past the Hopf point); the limit-cycle branches grow from it at Re_c. The orders coincide near Re_c and separate with distance — the expected behaviour of a truncated expansion.
FIG · 03 Period-averaged fluctuation kinetic energy vs Re (interactive). The horizontal line is the steady branch (solid = stable, dashed = unstable); the fluctuation energy grows from zero at the Hopf point Re_c ≈ 48.98. Where the orders agree the truncation is converged.
Convergence with expansion order

Where the truncation orders separate, the reduced state has moved outside the region where the expansion converges — the order-5 branch even folds back around Re ≈ 54.6, a truncation artifact rather than physics. This is why the order study matters before relying on any single curve.

Recap

  1. Fixed point — converge a steady state (Newton–Raphson) and linearise around it: $(\mathbf B_0, \mathbf B_1)$.
  2. Nonlinearities — declare each term of $F(x,r)$ as a MultilinearMap (matrix/vector) or FEMMultilinearMap (element-level assembly), with its state/external signature.
  3. Parameters — anything that enters (multi)linearly can be carried as an ExternalSystem coordinate; the ROM becomes parametric.
  4. Masters — pick the eigenpairs that span the physics (here the Hopf pair) and hand MORFE both right and left eigenvectors.
  5. Style — the resonance set decides what survives in $\dot z = R(z)$; normal-form style keeps the minimal resonant core.
  6. Solve & use — solve_cohomological_problem returns $(W, R)$; continuation runs on $R$, physical quantities come from projections of $W$.
